# github-trend-scout

Автономный конвейер обзоров GitHub-репозиториев. Раз в три дня GitHub Actions запускает Python-пайплайн, который собирает свежие перспективные репозитории, отсеивает их по метрикам, прогоняет через статические анализаторы безопасности, разбирает каждую находку через LLM (Groq) и публикует готовый сценарий YouTube-выпуска на русском языке прямо в этот репозиторий.

Репозиторий работает без ручного участия: расписание, анализ, текст сценария и коммит результата делает workflow. Всё, что попадает в `output/`, — машинный результат конкретного прогона: сценарий, список репозиториев и полные данные анализа с отчётами сканеров.

## Как это работает

```
[GitHub Actions cron]
        │
        ▼
┌──────────────────┐
│ 1. Ingestion     │  → сбор кандидатов (Search API)
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 2. Pre-filter    │  → отсев по метрикам (stars, license, activity)
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 3. Security scan │  → semgrep / bandit / gitleaks / osv-scanner
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 4. LLM analysis  │  → Groq: полезность, уникальность, ЦА, минусы
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 5. Scoring/Rank  │  → итоговый скор, выбор топ-10
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 6. Script gen    │  → Groq: сценарий YouTube на русском
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 7. Publish       │  → коммит в output/ + обновление README
└──────────────────┘
```

Формула итогового скора:

```
final_score = 0.40 * analysis.score
            + 0.25 * log10(stars+1)/5
            + 0.15 * recency_bonus
            + 0.10 * (1 if security.passed else 0)
            + 0.10 * activity_bonus
```

Репозитории с `critical`-находками сканеров и с оценкой LLM ниже 3 в выпуск не попадают.

Повторов не бывает: всё, что однажды вышло в выпуске, попадает в [`output/archive.json`](output/archive.json) — файл коммитится вместе с выпуском и служит постоянным фильтром. Кандидат из любого прошлого выпуска отсекается до сканирования и анализа. Дополнительно `data/state.db` не даёт повторно анализировать репозитории, обработанные меньше трёх дней назад (локальный кэш, в git не попадает). Если после отсева не осталось ни одного нового репозитория, выпуск не публикуется — прогон завершается успешно с записью в лог.

## Последний выпуск

Индекс всех выпусков — [`output/README.md`](output/README.md). Каждый выпуск лежит в `output/YYYY-MM-DD/`:

- `script.md` — готовый сценарий видео;
- `repos.json` — репозитории выпуска;
- `analysis.json` — полный разбор: оценка, плюсы/минусы, ЦА, отчёт безопасности.

## Установка и локальный запуск

```bash
git clone https://github.com/kort0881/github-trend-scout.git
cd github-trend-scout
cp .env.example .env      # впишите GROQ_API_KEY
pip install -r requirements.txt
python -m src.main
```

Тесты (сеть и LLM замоканы):

```bash
pip install -r requirements-dev.txt
pytest
```

Для полного локального прогона со сканерами безопасности поставьте `semgrep`, `bandit`, `gitleaks`, `osv-scanner` — отсутствующие сканеры не ломают пайплайн, а пропускаются с предупреждением в лог.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `GROQ_API_KEY` | да | — | ключ Groq API |
| `GITHUB_TOKEN` | нет (рекомендуется) | — | повышает лимиты GitHub API |
| `GROQ_MODEL` | нет | `openai/gpt-oss-120b` | модель Groq |
| `GROQ_FALLBACK_MODELS` | нет | `llama-3.3-70b-versatile` | резервные модели через запятую (если основная пропала из каталога) |
| `MAX_REPOS` | нет | `10` | сколько репозиториев в выпуске |
| `MIN_STARS` | нет | `100` | минимальный порог звёзд |
| `LOOKBACK_DAYS` | нет | `3` | окно поиска, дни |
| `CANDIDATE_LIMIT` | нет | `50` | сколько кандидатов собирать за прогон |

В GitHub Actions ключ хранится в `Settings → Secrets and variables → Actions` как `GROQ_API_KEY`.
